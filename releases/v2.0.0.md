# Conlab v2.0.0 GenAI MVP

Conlab v2.0.0 adds the first GenAI-supported workflows to the controlled collaboration text ledger.

This release keeps the v1 Git-backed collaboration model and adds local GenAI assistance for contribution control and narrative creation.

## What Is New

- GenAI plausibility review before posting into content buckets
- Checks whether a contribution is mainly one clear statement
- Checks semantic overlap against the current visible rendered bucket content
- Suggests shorter, crisper rewrites for proposed posts
- Prompt bucket type for storing reusable prompts in the same governed ledger model
- Prompt buckets skip GenAI contribution review but still follow bucket review/auto-accept settings
- Narrative generation modal
- Narrative generation from one selected prompt bucket and one or more selected content buckets
- Copyable generated narrative output
- Local GenAI endpoint, model, and API key settings stored in browser/app local storage

## Existing Features Kept From v1.0.0

- Git-backed workspace storage through `conlab.json`
- GitHub and GitLab repository support
- Repository role mapping into Conlab roles
- Content buckets with create, revise, and delete event actions
- Questions and decisions
- Markdown rendering
- Rendered bucket text history navigation
- Markdown export of visible rendered bucket state
- In-app polling notification for remote workspace updates
- Tauri macOS desktop packaging path

## GenAI Usage Model

Each user provides their own GenAI API key locally. The key is not stored in `conlab.json` and is not committed to Git.

The current GenAI implementation calls the configured endpoint directly from the local app/browser session. This is intended for trusted local/VPN usage.

## Prompt Buckets

Prompt buckets are normal Conlab buckets with `Bucket type` set to `Prompt`.

They store reusable GenAI instructions as reviewed ledger content. This lets a team evolve prompts in the same controlled way as other collaboration text:

- add prompt instructions as content events
- revise prompt instructions through new ledger entries
- delete outdated prompt instructions without mutating history
- use review-required or auto-accept mode depending on the bucket configuration

Only accepted visible prompt content is used when the prompt bucket is selected for narrative generation. Rejected, deleted, superseded, or non-rendered prompt entries are ignored.

Prompt buckets skip the GenAI contribution plausibility check. The intent is to govern prompt changes through Conlab's event/review workflow, not through the content-quality check used for source material.

Example prompt bucket content:

```md
You write concise executive narratives from controlled source material.
```

```md
Use only the selected bucket content. Do not invent facts.
```

```md
Prefer direct language. Avoid generic marketing claims and unnecessary adjectives.
```

## Narrative Generation Workflow

Use `Create narrative` to select:

- one prompt bucket
- one or more content buckets

The selected prompt bucket provides the GenAI instruction. The selected content buckets provide source material in the order shown in the modal.

The generated narrative is shown in the modal and can be copied out. In v2.0.0, generated narratives are not yet persisted back into the ledger.

## Desktop Packaging

Build the macOS bundle with:

```bash
make desktop-build
```

Generated artifacts are written under:

```text
src-tauri/target/release/bundle/
```

Ad-hoc signed `.dmg` builds can be uploaded directly to GitHub Releases for MVP distribution. macOS may show a Gatekeeper warning on first launch because the app is not Apple-notarized.

## Install

For local browser usage:

```bash
make run
```

For desktop bundle creation:

```bash
make desktop-build
```

## Known Limitations

- No automatic app updater yet. New versions are installed by downloading the next `.dmg` and replacing the old app.
- Desktop builds are ad-hoc signed but not Apple-notarized.
- Tokens and GenAI keys are stored locally in browser/app local storage.
- Narrative generation output is copy-out only in this release; it is not persisted as a new ledger event yet.
- Content bucket order for narrative generation is the order shown in the modal.
- No shared/cloud BFF is included.
